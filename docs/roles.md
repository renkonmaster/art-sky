# バックエンドとフロントエンドの役割分担

## 方針

- **フロントエンド**：画面の表示と作品の描画だけを行う。トークンや投稿履歴は持たない。
- **バックエンド**：ログイン、Bluesky と PDS への読み書き、作品の生成、ギャラリー用の索引を受け持つ。
- 2 つは下の「API」だけでつながる。API の形を先に決めれば、別々に開発できる。

```
[フロントエンド] ──HTTP(API)──> [バックエンド] ──> Bluesky / 本人の PDS
       │                              │
  作品の描画（renderer）       生成時の検証（renderer）
```

## フロントエンドのやること

### 画面

| 画面 | ログイン | 内容 |
|---|---|---|
| 全体ギャラリー | 不要 | 参加者ごとの最新作品、作者名、更新日時 |
| 個人ギャラリー | 不要 | 1 人の最新作品と過去作品（時系列） |
| 作品詳細 | 不要 | 作品、作者、生成日時、元投稿へのリンク、前後の作品へのリンク |
| ログイン | ― | ハンドル名の入力 |
| 初回登録 | 必要 | 外部 AI に送る内容の説明と同意、最初の作品の生成開始 |
| 投稿 | 必要 | 投稿フォーム、投稿結果、生成状況 |
| 管理 | 必要 | 生成ジョブの一覧と再試行、生成停止、ギャラリー掲載の設定 |

### その他

- `packages/renderer` を使い、作品レコードの `code` を別オリジンの iframe で描画する。
- 生成中のジョブは、完了するまで一定間隔で状態を取得して表示を更新する。
- ログイン状態は、バックエンドが発行する HttpOnly の Cookie だけで保つ。トークンには触れない。

## バックエンドのやること

| 役割 | 内容 |
|---|---|
| ログイン | OAuth（ローカルではループバッククライアント）、セッション Cookie の発行、トークンの保存と更新 |
| 初回登録 | 直近 100 件の投稿と総投稿数などを取得し、最初の作品の生成ジョブを登録する |
| 投稿 | Bluesky に投稿し、生成ジョブを登録する |
| 作品の生成 | Claude API で描画関数を生成し、Chromium で検証して、本人の PDS に保存する |
| ジョブ管理 | 状態とエラーの記録、再試行、重複の防止 |
| 設定 | 生成停止、ギャラリー掲載 |
| ギャラリーの索引 | Jetstream で作品レコードを受け取り、検証して索引に入れる。掲載しない人の作品は除く |
| ギャラリー API | 索引から一覧と詳細を返す |

バックエンドの中でも、**生成**（PDS に書く）と**索引**（PDS から読む）はモジュールを分ける。
両者は PDS を介してだけつながるので、索引は PDS からいつでも作り直せる。

## API

詳細は [api.md](api.md)、定義は `packages/api` と `lexicons/com/example/artsky/gallery/` にある。

| 種類 | パス | ログイン |
|---|---|---|
| 認証（画面遷移） | `/oauth/login`、`/oauth/callback`、`/oauth/logout` | ― |
| ログイン中のユーザー | `GET /api/me` | 不要 |
| 初回登録 | `POST /api/register` | 必要 |
| 投稿 | `POST /api/posts` | 必要 |
| ジョブ | `GET /api/jobs`、`GET /api/jobs/:id`、`POST /api/jobs/:id/retry` | 必要 |
| 設定 | `GET /api/settings`、`PATCH /api/settings` | 必要 |
| ギャラリー（XRPC） | `listLatest`、`listByActor`、`getArtwork` | 不要 |

## ローカルでの構成

| もの | URL |
|---|---|
| フロントエンド（Vite） | `http://127.0.0.1:5173` |
| バックエンド（Hono） | `http://127.0.0.1:3000` |
| 描画用 iframe | `http://127.0.0.1:5174` |

- Vite のプロキシで `/api`、`/oauth`、`/xrpc` をバックエンドに転送する。
  フロントエンドとバックエンドが同じオリジンに見えるので、Cookie や CORS の設定が要らない。
- ループバッククライアントの戻り先は `127.0.0.1` で指定する必要があるので、`localhost` ではなく `127.0.0.1` で開く。
- 描画用 iframe はポートを変えて別オリジンにし、作品のコードからページ本体に触れないようにする。

## 別々に開発する方法

- **フロントエンド**：API のモック（サンプルの作品レコードとジョブ）を用意すれば、バックエンドなしで画面を作れる。
- **バックエンド**：API を curl などで呼び、PDS に保存されたレコードを `com.atproto.repo.listRecords` で確かめる。
- **共通部品**：`packages/lexicon` と `packages/renderer` は両方が使うので、最初に作る。
